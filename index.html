How the Solver Works

The engine is a classic backtracking depth-first search over the space of legal grids, accelerated with the MRV (Minimum Remaining Values) heuristic and bitmask constraint propagation. Together these turn an NP-sized brute-force problem into a millisecond-scale search for virtually any 9×9 puzzle.

01

Bitmask Constraint Tracking

Every row, column and 3×3 box keeps a 9-bit integer — bit d−1 set means digit d is already used. The legal candidates of a cell are computed in a single expression:

cand = 0x1FF & ~(rowMask | colMask | boxMask)

No loops over 9 cells, no sets, no allocations — just three ORs, one NOT and one AND, making each constraint check effectively O(1).

02

MRV Heuristic

Instead of filling cells left-to-right, the solver always branches on the empty cell with the Minimum Remaining Values — the fewest legal candidates.

A cell with one candidate is a forced move (free constraint propagation), and a cell with zero candidates proves the branch is dead instantly. This single decision rule shrinks the search tree from millions of nodes to a few hundred on typical puzzles.

03

Backtracking DFS

The solver performs a depth-first search: place a digit, update the three unit masks, recurse. If the subtree fails, the digit is removed (masks restored with bitwise AND-NOT) and the next candidate is tried.

Every placement and rollback is recorded as a step, which powers the Watch Solving Process replay — you can literally watch the algorithm think, including its backtracks.

04

Uniqueness Verification

After the first solution is found, the search continues until a second complete grid appears or the space is exhausted (capped at 2 solutions).

This tells you whether your puzzle has a unique solution — the standard requirement for a proper Sudoku — or is underconstrained. The app flags the difference in the results panel.

Search Loop in Pseudocode

search(): if board is complete: # 81 digits, all constraints hold record solution; return true cell ← empty cell with FEWEST candidates # MRV heuristic if candidates(cell) = ∅: # contradiction detected early prune this branch for d in candidates(cell): # iterate set bits of the 9-bit mask place d; rowMask |= d; colMask |= d; boxMask |= d if search(): return true # descend depth-first remove d; restore masks # ← backtracking return false # all candidates failed

Complexity. Worst-case Sudoku search is exponential (the problem is NP-complete in its generalized n² × n² form), but the MRV ordering makes practical instances tiny: an easy daily puzzle solves with zero backtracks, while the hardest known grids need only a few hundred. Memory usage is O(81) for the grid plus O(depth) for the recursion stack.
